# 纸上生花提交检查清单

## 1. 提交材料

|材料|对应文件|
|---|---|
|作品介绍、运行环境与使用说明|README.md、部署与演示.md|
|设计目标、参赛主题与方向、视觉和交互|设计说明.md|
|技术架构、几何模型、数据与权限|代码说明.md|
|测试结果与响应式适配范围|测试与限制.md、TESTING.md|
|功能库用途、素材和文化来源|依赖与素材来源.md|
|队伍名称、成员与分工|完整版附加TEAM.md|

## 2. 内容检查

- [ ] 主题名称统一为“匠心传承，非遗焕新”，参赛方向为门户网站。
- [ ] 补齐参赛组别，确认队伍资料与报名信息一致。
- [ ] 文档中的页面、功能和界面文字与提交版本一致。
- [ ] 按部署说明完成初始化、创作、保存、恢复、投稿及后台更新流程。
- [ ] 测试数据、模拟方法与适配范围标注清楚。
- [ ] 依赖用途、许可证、文化来源和素材信息齐全。

## 3. 完整版与匿名版

完整版与匿名版保持相同程序功能。完整版README附加队伍信息；匿名版保留作品介绍、技术说明与使用方法，去除选手身份。

|保留内容|排除内容|
|---|---|
|app、server、shared、db、public、scripts、tests、docs|.git、node_modules、构建缓存、日志、截图|
|README、TESTING、package.json、package-lock.json|真实.env、运行数据、原始比赛材料|
|.env.example、Nuxt与TypeScript配置、Docker Compose配置|匿名版中的队伍身份与开发仓库线索|

现有打包脚本的白名单需补入docs，并确保中文文件名采用UTF-8编码。

### 匿名检查

- [ ] README、文档、源码注释、SVG元数据不含选手个人信息。
- [ ] 不包含TEAM.md、真实.env、数据库数据或开发者账号信息。
- [ ] Markdown相对链接在提交目录中有效。
- [ ] 匿名处理保留必要功能、文化来源和第三方许可证。

## 4. 命名与收件

手册给出的外层命名结构为`零杯{组别}-{队伍名}-{队长姓名}.zip`，内部包含完整版和匿名版两个子压缩包。组别使用实际报名组别，斜杠不是文件名的一部分。

提交前确认两项存在差异的规定：手册收件时间为11月14日22:00，开幕式材料写初赛至11月16日；匿名子包命名示例包含队长姓名，正文却要求不含个人信息。最终按赛事组确认的口径填写。

重复提交时，在邮件正文说明版本变化，并以最后一次提交内容为准。

# 纸上生花环境配置与部署演示

本文用于统一开发和评审演示环境。先完成依赖、环境变量及数据库初始化，再启动网站。命令默认在Windows PowerShell、项目根目录执行。

本项目采用：

```text
前端：Nuxt 4 + Vue 3 + TypeScript + 原创 CSS / SVG
服务端：Nuxt Nitro（与前端在同一项目运行）
数据库：PostgreSQL 17
数据库启动方式：Docker Desktop + Docker Compose
Node.js：推荐 24，最低 22.12
```

---

## 1. 项目技术栈

### 1.1 页面与交互

- Nuxt 4.4.2：页面、文件路由、SSR与构建。
- Vue 3、TypeScript：组件、响应式状态及类型约束。
- 原创CSS和SVG：排版、剪纸模型、场景与动效。

### 1.2 服务端与数据库

- Nitro：与页面同源提供`/api`接口，无需另开Python或其他后端项目。
- node-postgres：直接执行参数化SQL，不使用ORM。
- PostgreSQL 17：保存草稿、作品、会话、文化内容、学习进度与发布状态。
- SQL版本迁移及种子：分别由`db:migrate`和`db:seed`执行。

精确依赖及用途见[依赖与素材来源](依赖与素材来源.md)。

## 3. 进入项目并安装依赖

进入项目根目录，安装锁文件中指定的依赖：

```powershell
npm ci
```

从源码包开始时，先解压到自己的项目目录，再在该目录运行`npm ci`。安装需要联网；不要把目录名当成固定路径。安装完成后继续配置数据库。

## 4. 根目录环境变量

### 4.1 首次创建配置

```powershell
Copy-Item .env.example .env
```

已有`.env`时保留原文件，手动对照示例补齐新变量，不要直接覆盖密码。

### 4.2 配置项目

|变量|用途|
|---|---|
|DATABASE_URL|连接PostgreSQL，数据库用户paper、库paperstudio、本机端口55432|
|PG_LOCAL_PASSWORD|Docker或本机数据库初始化密码，至少12位，与连接串密码一致|
|ADMIN_USERNAME|自行设置的管理员用户名|
|ADMIN_PASSWORD|管理员初始化密码，至少12位|
|SITE_URL|浏览器实际访问的根地址，默认http://127.0.0.1:3000|
|PORT|应用端口，默认3000|
|HOST|应用监听主机，默认127.0.0.1|

示意配置如下，密码必须自行替换，不要照搬占位值：

```dotenv
DATABASE_URL=postgresql://paper:YOUR_DATABASE_PASSWORD@127.0.0.1:55432/paperstudio
PG_LOCAL_PASSWORD=YOUR_DATABASE_PASSWORD
ADMIN_USERNAME=YOUR_ADMIN_USERNAME
ADMIN_PASSWORD=YOUR_ADMIN_PASSWORD
SITE_URL=http://127.0.0.1:3000
PORT=3000
HOST=127.0.0.1
```

密码如含连接串保留字符，须在DATABASE_URL中正确编码。`.env`不提交Git，也不写入参赛文档。终端环境变量优先于`.env`；排查旧端口配置时同时检查终端。

## 5. 使用Docker Desktop启动数据库

### 5.1 启动前确认

1. Docker Desktop已打开，Engine运行正常。
2. 终端位于含docker-compose.yml的项目根目录。
3. `.env`密码已填写，55432端口未被另一套数据库占用。

### 5.2 启动与检查

```powershell
docker compose up -d db
docker compose ps
docker compose exec db pg_isready -U paper -d paperstudio
```

`db`服务为running／healthy，且pg_isready提示接受连接，说明数据库就绪。查看日志可执行：

```powershell
docker compose logs --tail 50 db
```

### 5.3 停止

```powershell
docker compose stop db
```

数据存储在Compose命名卷中。正常停止、重启不需要删除卷；不要通过删库来执行版本升级。只启动数据库容器不会自动运行本项目的迁移与业务种子。

## 7. 数据库迁移与初始内容

### 7.1 执行迁移

```powershell
npm run db:migrate
```

当前迁移为001–004，包含基础表、独立教程练习、展示投稿即时公开与默认教程提示更新。脚本记录校验和并跳过已执行迁移；已经执行的SQL文件不能原地修改。

### 7.2 首次写入种子

```powershell
npm run db:seed
```

种子包括8个纹样、6篇文化札记、3个教程、6件标记为原创示例的作品，并初始化管理员。重复运行会保留既有内容，但会按当前环境变量重设管理员密码。

已有数据库升级一般只运行迁移；不需要每次演示都运行种子。后台修改后的内容由数据库决定，不会因修改seed文件自动覆盖。

## 8. 启动应用

### 8.1 开发模式

```powershell
npm run dev
```

默认访问http://127.0.0.1:3000，页面与Nitro接口同时启动。

### 8.2 生产预览

```powershell
npm run build
npm start
```

`npm start`读取`.output`构建产物。修改或拉取源码后，应停止旧应用、重新构建并启动，再刷新浏览器。清理过`.output`时也必须先构建。

### 8.3 验证入口

|入口|地址|
|---|---|
|首页|http://127.0.0.1:3000/|
|数据库健康检查|http://127.0.0.1:3000/api/health|
|剪纸工坊|http://127.0.0.1:3000/studio|
|公开展览|http://127.0.0.1:3000/gallery|
|后台|http://127.0.0.1:3000/admin|

健康接口成功时返回`ok: true`和`database: postgresql`。后台使用自行配置并通过种子初始化的管理员账号。

### 8.4 更换预览端口

在启动应用的终端中设置，例如使用空闲的3117端口：

```powershell
$env:PORT='3117'
$env:NITRO_PORT='3117'
$env:SITE_URL='http://127.0.0.1:3117'
npm start
```

之后所有页面与测试脚本使用相同根地址。切回3000时同步修改这些变量或新开终端，不要只修改浏览器地址。

## 9. 手机局域网预览

1. 手机与电脑连接同一局域网。
2. 用`ipconfig`查电脑局域网IPv4地址。
3. 完成生产构建，在启动终端设置监听地址和实际访问地址。以下IP只是示例：

```powershell
$env:HOST='0.0.0.0'
$env:PORT='3000'
$env:NITRO_PORT='3000'
$env:SITE_URL='http://192.168.1.100:3000'
npm start
```

手机和电脑均使用实际局域网地址访问，检查防火墙是否允许应用端口。手机上的127.0.0.1指向手机自身。数据库仍只由电脑上的应用访问，不需要向局域网开放数据库端口。

生产来源校验使用SITE_URL，地址不一致可能导致保存403。结束后可新开终端恢复本机配置。

## 10. 日常更新与检查

1. 保留已有`.env`、数据库数据和浏览器访客Cookie。
2. 依赖变化时运行`npm ci`，迁移变化时运行`npm run db:migrate`。
3. 开发模式直接调试；生产预览需重新构建和重启。
4. 按改动执行单元、类型或浏览器检查；维护当前文档和TESTING中的实际结果。

```powershell
npm test
npm run typecheck
```

浏览器脚本需已有应用与数据库，先设置一致的SITE_URL。

## 11. 常见问题

### 12.1 数据库无法连接

检查Docker服务或本机数据库进程是否启动、55432端口是否冲突，以及DATABASE_URL密码是否匹配。可先看Compose日志及pg_isready结果，不要删除已有数据排错。

### 12.2 页面没有种子内容

确认迁移和首次seed执行成功，并访问`/api/health`。后台可能取消发布内容，正常的空状态不能直接视为程序出错。

### 12.3 保存返回403

检查Cookie、SITE_URL、实际访问地址和应用版本。写接口先获取会话绑定的CSRF令牌；旧生产进程不会因源码改变自动更新。不要关闭安全校验，也不要把Cookie或令牌发送到聊天。

### 12.4 保存返回409

通常是旧版本、练习记录或作品状态变化。保留当前编辑，刷新对应纸笺或另存新草稿，避免覆盖别的标签页更新。

### 12.5 修改源码后预览没变化

开发模式和生产模式分别启动；若使用npm start，必须重新构建并重启。清理缓存后先运行npm run build，才能再次运行npm start。

### 12.6 草稿找不回或管理员密码变化

草稿依赖当前浏览器Cookie，不提供跨设备账户找回。管理员密码由seed按环境配置初始化或重设；不要无意重复运行种子。

## 12. 最小验收链路

- [ ] 数据库健康检查成功，首页、学堂、教程和展览有内容。
- [ ] 工坊添加切口、调整、撤销重做和展开正常。
- [ ] 保存成功后刷新可恢复同一作品，纸笺能继续编辑。
- [ ] 投稿立即公开，展览详情显示同一张作品。
- [ ] 后台修改札记，前台正文随之更新。
- [ ] 手机上能完成主要操作；减少动态效果时仍可阅读与创作。

测试方法及结果见[测试与适配说明](测试与限制.md)。

## 13. 三分钟演示

1. 首页看双燕与留白，从纸窗进入学堂，切换纹样并打开札记查看来源。
2. 用390px模拟手机视口进入工坊，添加圆孔与水滴，调整、撤销、重做并展开。
3. 命名保存，刷新恢复，再下载SVG或透明PNG。
4. 投稿自动通过，打开公开详情或到展览搜索作品名，无需先由管理员操作。
5. 后台修改文化正文，回前台核对；可补充演示三景动画、窗影、装裱外圈及减少动态效果。
